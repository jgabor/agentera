Agentera gives one coding agent shared project state, specialized capabilities,
and behavioral verification gates.

## First-run flow

1. Pick your runtime and [install Agentera](/docs/getting-started/install/).
2. Open a git project (existing repo or new).
3. Run `/agentera` (`$agentera` in Codex).

Supported runtime identities: OpenCode, Codex, Cursor, and GitHub Copilot.
Cursor Agent CLI is required and Cursor IDE is conditional beneath one Cursor
identity. The canonical skill path is `~/.agents/skills/agentera`.
See [install steps](/docs/getting-started/install/) for runtime-specific wiring.

Your first briefing bootstraps `.agentera/` as capabilities run. The briefing
pulls from plan, progress, decisions, health, and issues — but only the slices
that matter right now.

## What you see

The dashboard shows project health, open issues, plan progress, profile status,
attention items, and a suggested next capability. Wide coverage, narrow reads:
many artifacts, token-efficient handoffs.

Capabilities update `progress`, `decisions`, `plan`, and `health` through the
typed state writer. See the [state writer reference](/docs/reference/state-writer/)
for discovery commands, dry runs, and examples.

## After your first briefing

Run `/agentera profile` to teach Agentera how you decide. The profile travels
across projects while repo artifacts stay project-local.

## CLI without a clone

```bash
npx -y agentera@next prime --format json
npx -y agentera@next doctor --format json
```

`prime` is the bounded project/runtime summary. Use `doctor` for detailed
read-only lifecycle evidence. Agentera 3.0 remains on `@next` until the stable
dist-tag promotion.
