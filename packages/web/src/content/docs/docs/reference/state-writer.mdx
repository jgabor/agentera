---
title: State writer
description: Discover, preview, and safely mutate Agentera entity state.
---

Agentera stores ordinary mutable state as one canonical file per entity. Every
public record has a bare `id` and an `artifact` classification. Use the CLI for
bounded lists, exact `get --id` reads, and typed mutations; do not edit
`.agentera/entities/` directly.

Intentional singletons such as vision, documentation policy, changelog, design,
and profile retain their declared file boundaries.

## Discover the live contract

Run `explain` before constructing a mutation. It reports the supported verbs,
fields, valid values, defaults, budgets, and an executable example.

```bash
agentera state decisions explain --format json
agentera state decisions explain --verb update --format json
agentera state plan explain --verb set-status --format json
agentera state health explain --verb append --format json
```

The complete machine-readable operation matrix is available from:

```bash
agentera schema --format json
```

## Read bounded and exact state

Collection commands return bounded pages, omission metadata, and opaque
snapshot cursors. Use the matching exact command for full detail.

```bash
agentera state progress list --limit 20 --format json
agentera state progress get --id PROGRESS_ID --format json
agentera state plan tasks list --plan-id PLAN_ID --format json
agentera state plan tasks get --id TASK_ID --format json
```

## Preview and publish mutations

Add `--dry-run` where the discovered verb supports it. Remove the flag only
after reviewing the validated candidate.

```bash
agentera state progress append \
  --type fix \
  --phase build \
  --what "Made writer discovery available from prime." \
  --intent "Let agents find the safe mutation path." \
  --verified "CLI tests and typecheck passed." \
  --dry-run \
  --format json
```

The CLI assigns the entity ID and publishes exactly one writer-owned file.

## Update an existing entity

Existing records are selected by bare ID. Decision satisfaction and plan-task
lifecycle updates never use ordinal selectors.

```bash
agentera state decisions update \
  --id DECISION_ID \
  --satisfaction-state provisionally_satisfied \
  --satisfaction-evidence "The implementation and regression tests now exist." \
  --format json

agentera state plan set-status \
  --id TASK_ID \
  --status complete \
  --format json
```

Only the user can establish `user_confirmed_satisfied`; agents may record
provisional satisfaction with evidence.

## Structured input

Plan creation and health audits accept validated YAML or JSON input. Their
published entities still receive CLI-owned `id` and `artifact` fields.

```bash
agentera state plan create --input plan.yaml --format json
agentera state health append --input audit.yaml --format json
agentera state health append --input - --format json < audit.json
```

Run the matching `explain --verb <verb>` command for the current input schema
and lifecycle rules.
